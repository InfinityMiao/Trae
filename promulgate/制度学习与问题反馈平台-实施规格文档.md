## 1. 概述

### 1.1 目标

构建一个面向企业内部员工的制度学习与问题反馈平台，包含制度学习、在线考试、问题反馈三大核心功能，配备完整的后台管理系统。

### 1.2 技术栈

| 层级     | 技术                                                           |
| ------ | ------------------------------------------------------------ |
| 前端     | Vue 3 + Element Plus + Pinia + Axios + Vue Router + Vite     |
| PDF    | pdfjs-dist（前端渲染 + Canvas 水印）                                 |
| Excel  | ExcelJS（前后端共用）                                               |
| 后端     | Express + TypeORM + jsonwebtoken + Multer + bcrypt + ExcelJS |
| 数据库    | MySQL 8.0                                                    |
| API 风格 | RPC（`/api/xxxService.method`）                                |
| 认证     | JWT（无状态 Token）                                               |
| 文件存储   | 本地存储（服务器目录）                                                  |
| 部署     | Docker + Docker Compose                                      |

| 阶段         | Task 范围    | 说明                         |
| ---------- | ---------- | -------------------------- |
| 阶段1：基础设施   | Task 1-4   | 项目初始化、数据库、认证、通知、管理员登录      |

## 2. 数据库设计

### 2.1 ER 关系

```
departments 1──N positions
departments 1──N employees (via department_id)
positions   1──N employees (via position_id)

regulation_categories (树形 self-ref, 含系统内置分类)
regulation_categories 1──N regulations

regulations N──M departments (via regulation_permissions)
regulations N──M positions   (via regulation_permissions)

exams N──M regulations (via exam_regulations)

employees N──M regulations   (via employee_learning)
employees N──M exams         (via exam_records)

employees 1──N feedbacks
employees 1──N feedback_replies (管理员回复)
feedbacks  1──N feedback_replies
feedbacks  1──N feedback_attachments
feedback_categories 1──N feedbacks
```

## 3. RPC API 完整清单

### 3.1 统一规范

**路径格式：** `POST /api/{service}.{method}`（所有接口统一使用 POST 方法）

**请求头：**

```
Authorization: Bearer <jwt_token>
Content-Type: application/json
```

**统一响应：**

```json
{ "code": 200, "message": "success", "data": { ... } }
{ "code": 400, "message": "错误描述", "data": null }
{ "code": 401, "message": "未登录或Token已过期", "data": null }
{ "code": 403, "message": "无权限", "data": null }
{ "code": 423, "message": "账号已锁定，请X分钟后重试", "data": { lock_minutes: X } }
{ "code": 500, "message": "服务器内部错误", "data": null }
```

**分页请求参数：** `{ page: 1, pageSize: 20 }`

**分页响应：**

```json
{
  "code": 200,
  "data": {
    "list": [...],
    "total": 100,
    "page": 1,
    "pageSize": 20
  }
}
```

**认证标注说明：**

| 标注  | 含义                               |
| --- | -------------------------------- |
| 无   | 不需要登录                            |
| 员工  | 需要登录且 `employee_type='employee'` |
| 管理员 | 需要登录且 `employee_type='admin'`    |
| 通用  | 需要登录，不限类型                        |

### 3.2 认证服务 — AuthService

| 方法   | 路径                              | 认证 | 说明     | 请求参数                                           | 响应数据                                    |
| ---- | ------------------------------- | -- | ------ | ---------------------------------------------- | --------------------------------------- |
| POST | /api/authService.login          | 无  | 统一登录   | `{ employee_no, password }`                    | `{ token, employee_type, first_login }` |
| POST | /api/authService.changePassword | 通用 | 修改密码   | `{ old_password, new_password }`               | `null`                                  |
| POST | /api/authService.resetPassword  | 无  | 密码找回   | `{ employee_no, id_card_last6, new_password }` | `null`                                  |
| POST | /api/authService.getUserInfo    | 通用 | 当前用户信息 | -                                              | 用户信息对象（含 employee\_type）                |

**业务规则：**

- **统一登录**：管理员和普通员工使用同一登录接口，通过 `employee_no + password` 登录
- 首次登录（`first_login=true`）强制修改密码
- 密码策略：≥8位，必须含大写+小写+数字
- 渐进锁定（三级）：

| 连续输错次数  | 锁定策略     |
| ------- | -------- |
| 3 次     | 锁定 5 分钟  |
| 5 次     | 锁定 30 分钟 |
| 10 次及以上 | 锁定 60分钟  |

- 锁定实现：3次/5次/10次均设置 `lock_until = NOW() + 对应分钟数`
- 锁定响应：`{ code: 423, message: "账号已锁定，请X分钟后重试", data: { lock_minutes: X } }`
- 禁用用户：返回 `{ code: 403, message: "账号已被禁用" }`

**getUserInfo 响应结构：**

```json
{
  "id": 1,
  "name": "张三",
  "employee_no": "A001",
  "employee_type": "employee",
  "department_id": 1,
  "department_name": "技术部",
  "position_id": 1,
  "position_name": "工程师",
  "employee_type": "employee"
}
```

> 登录响应新增 `employee_type` 字段，前端据此路由到不同界面（管理员→后台，普通员工→前台）。

**create 业务规则：**

- `employee_type`：可选 `'admin'` 或 `'employee'`，默认 `'employee'`
- 创建管理员时 `department_id` 和 `position_id` 可为 NULL
- 创建后用户使用 `employee_no + id_card_last6` 首次登录，强制修改密码

**update 业务规则：**

- 不允许修改 `employee_no` 和 `id_card_last6`
- 允许修改 `employee_type`（管理员↔普通员工互转）
- 将普通员工改为管理员时，`department_id` 和 `position_id` 可置为 NULL
- 将管理员改为普通员工时，`department_id` 和 `position_id` 不能为 NULL

**list 请求参数** **`employee_type`** **筛选：**

- 不传：返回所有员工（含管理员）
- `'employee'`：仅普通员工
- `'admin'`：仅管理员

**Excel 导入模板字段：** 姓名、工资编号、身份证后六位、部门、岗位

**getProfile 响应字段说明：**

- `learning_stats`: `{ total: 应学制度数, completed: 已完成数, completion_rate: 完成率 }`
- `exam_stats`: `{ total_exams: 参加考试次数, best_score: 最高成绩, is_passed: 是否有及格记录 }`

**create/update 业务规则：**

- `content`：考试题目内容（JSON 结构见数据库设计），直接存储在 exams 表中
- `regulation_ids[]`：考试关联的制度列表，用于确定哪些员工需要参加考试
- 参加考试人员 = 所有关联制度权限（部门/岗位）的并集

**upload 文件上传说明：**

- 支持 Excel（.xlsx）和 JSON（.json）格式文件上传
- Excel 格式：每行一题，列包含 题型/题目内容/选项A/选项B/选项C/选项D/正确答案/解析
- JSON 格式：与 content JSON 结构一致
- 上传后后端解析文件内容，自动填充 `content` 字段，`source` 设为 `upload`
- 解析失败返回 `{ code: 400, message: "文件解析失败：具体原因" }`

**updateStatus 业务规则：**

- 发布考试时，查询所有关联制度的权限（部门+岗位并集），找到对应员工，批量插入通知
- 通知内容：`{ title: "新考试发布", content: "考试「{name}」已发布，请及时参加" }`

**getByRegulation 业务规则：**

- 根据制度ID查询 `exam_regulations` 关联表，返回所有已发布的考试
- 用于制度学习页面"进入考试"按钮跳转

**submit 评分逻辑：**

- 单选题：精确匹配（`userAnswer === correctAnswer`）
- 多选题：完全匹配（排序无关，`sort().join(',') === sort().join(',')`）
- 判断题：精确匹配（`userAnswer === correctAnswer`，均为字符串数组如 `["正确"]`）
- 每题分值 = 100 / 总题数（取整）
- 总分 = 各题得分之和
- is\_passed = score >= pass\_score

## 5. PDF 安全防护方案

### 5.1 前端安全

| 防护项    | 实现方式                                          |
| ------ | --------------------------------------------- |
| 禁用下载   | 不提供下载按钮，隐藏浏览器下载入口                             |

## 11. 权限校验中间件

后端中间件根据 JWT 中的 `employee_type` 校验接口权限：

| API 认证标注 | 校验逻辑                                  |
| -------- | ------------------------------------- |
| 无        | 不校验 Token                             |
| 通用       | 校验 Token 有效即可                         |
| 员工       | 校验 Token 且 `employee_type='employee'` |
| 管理员      | 校验 Token 且 `employee_type='admin'`    |

```typescript
feedbackService.getDetailregulationCategoryService.tree
```
